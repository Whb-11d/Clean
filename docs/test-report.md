## 十万文件基准（T-11）

数据集：100 个子目录，每目录 1000 个一字节文件；大文件扫描最低 1 字节。全部 100000 个候选被识别，达到上限时 Truncated 为 true，错误为 0。每次完成后移除自己的测试树。

| 实现 | 生成耗时 | 扫描耗时 | 测试进程峰值工作集 | 取消返回延迟 |
| --- | ---: | ---: | ---: | ---: |
| 初版逐文件重复获取目录句柄 | 63.20 秒 | 288.37 秒 | 143,527,936 B（136.9 MiB） | 4 ms |
| 复用仍持有的目录句柄与按需路径缓冲 | 66.72 秒 | 32.82 秒 | 126,111,744 B（120.3 MiB） | 1 ms |

第二轮约 3047 文件/秒，相对初版约 8.8 倍；不代表清理速度或应用空闲内存。取消测量在扫描开始后约 150ms 请求取消。系统调用仍可能阻塞，不能保证所有设备下 2 秒完成。

## 已知技术限制

Windows Shell 回收站 API 接收路径，最后校验到实际操作之间仍有叶文件被同权限恶意进程替换的窗口。保持祖先目录句柄、文件读句柄与回调二次复核只能缩小窗口，不能声称完全消除；见 ADR-002。永久删除使用已验证句柄。未能获得完整文件身份的文件系统拒绝处理。

历史为每项完成后持久化：进程在系统操作返回与落盘之间崩溃时，历史可能只记录最后确认结果；重启明确显示中断，不推测成功、不自动重试。回收站恢复由 Windows 提供，永久删除不保证可恢复。

依赖检查：`dotnet list Clean.slnx package --vulnerable --include-transitive` 对六个项目未报告已知易受攻击包（检查当日源数据，非“无漏洞”保证）。运行依赖许可和附带声明已核查并收录到 licenses/。远程 GitHub CI 仅配置，尚未真实运行。
